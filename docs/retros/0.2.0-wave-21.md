## 4. Proposals (evidence in brackets)

1. **Lead runbook: never block on `AskUserQuestion` mid-wave** (S1). Add a standing rule in `docs/software-factory.md` and
   the skill: disk below 25 GB means delete finished sessions' scratchpads and `target` dirs, notify, and continue; a
   question that needs the user is posted once and the wave carries on with other work.
2. **Rewrite `docs/software-factory.md` and `.claude/skills/factory/SKILL.md` for unnamed background subagents** (S2, S3):
   sections at lines 4, 68, 176, 189, 425-436, 476-499, 545, 552 and skill items 2, 9 still say teammate, claim panes,
   `SendMessage`, "stop idle teammates". State the real cap (seven tasks started, three open PRs), that every agent returns its
   report through the handback (no report files; critics and adversarial have no Write), and drop the pane budget.
3. **Agent files: add one rule to every implementer, critic and integrator: "never start a background job and stop; run it in
   the foreground with `timeout`, or poll its log"** (S3: 44 notices). Today it is only in the runbook.
4. **`adversarial-tester`: hand back (not "write a file") by turn 60** (21.4 repeat). Keep high/opus and xhigh for new
   surfaces (21.1 found a real blocker for 44k tokens). Experiment: `medium` for Swift tasks whose logic is in Rust
   (Settings panes, Plugins, Keys): 0 of 10 Swift runs produced an accepted blocker for ~620k tokens; keep high for
   AppDelegate, windows, signals and link policy (#458 M1 and #414 residual were real).
5. **Triage rule for adversarial minors**: a finding that writes wrong data into the user's config or loses user data is a
   BLOCKER for the task that exposes it, or a same-wave task, never a #430 minor (21.6a M1/M2 -> 21.4 B1 -> #455).
6. **Critic r2 only when a fix adds behaviour** (r2 58k tokens, 1 new blocker in 5: keep for #461-class fixes; skip for test
   or list fixes). Ask the critic of a behavioural fix to attack the fix's own new code paths first (#461 B2, F1 were
   introduced by the fix).
7. **Merge flow (decision for the user)**: turn off "require branches up to date" for the macOS job, or accept
   one update-branch per PR without a rerun. Evidence: 0 of the wave's main push runs failed after merge, 4 restarts cost
   35 min and P8 discipline still hit BEHIND three times (S5). Risk: a semantic conflict reaches main; the push run catches it.
8. **CI path skip**: tighten `scripts/ci-app-affected.sh` to skip macOS for `crates/*/tests/**`, `docs/**`, `scripts/**`, and
   crates the Swift tests do not exercise (`tessera-term`, `tessera-grid`, `tessera-vt` behind the FFI C test), or revert
   #459 (S6: 0 observed skips). Also print the last 30 lines of a failed xcodebuild step and upload the full log (S7).
9. **Toolchain parity**: install Xcode 16.4 beside the beta (or run `xcodebuild` for the gate with `DEVELOPER_DIR` pointing
   at it) before the first Swift gate of a wave (S7).
10. **Cap and load**: keep seven started, but gate a new implementer on `uptime` load average below 2x cores and free disk
    above 40 GB; the throughput evidence says the merge chain, not the cap, binds (S4). Bundle rule: only same-job PRs, two
    commits at most, built on merged main, not stacked on an open PR (S10).
11. **Brief index**: a `merged: #PR` column updated by the lead at merge, and one `gh pr list --search "<issue>" --state merged`
    check before spawning (S8). Cheap, avoids 6-compaction memory loss.
12. **Models and effort, no change**: implementers high/opus (27% + 21% of tokens, mutants killed and cost proportional to
    task size); critics high/opus (26% revise, real blockers); integrator sonnet/medium (1% of tokens, caught the stale
    app-test pass); spec-researcher kept (63-row fixture, 21.2 had no spec defect); release-engineer sonnet fine for #459/#462.

Not verified: per-gate minor counts are from handbacks (+-3); crit-21-0b and the first-cycle adversarial verdicts of
